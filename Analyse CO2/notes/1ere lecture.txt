  4. Le dataset CO2 (NOAA GML, co2_mm_gl.csv)

  Moyennes mensuelles globales en ppm, 561 observations utiles. Colonnes :
  - year, month, decimal (date décimale)
  - average : moyenne mensuelle
  - average_unc : incertitude
  - trend : moyenne désaisonnalisée
  - trend_unc : incertitude du trend

  Les valeurs vont de 336.56 ppm (jan 1979) à 426.87 ppm (avr 2025) → +90 ppm sur 46 ans, signal très propre. Pour
  la corrélation, je recommande d'utiliser trend (déjà désaisonnalisé) pour éviter de mélanger le cycle saisonnier
  CO2 avec le cycle saisonnier climatique.

  5. Implication technique majeure pour R

  R ne lit pas nativement le GRIB2. Trois voies possibles :

  ┌────────────────────────────────────────────────────────┬──────────────────────────────────────────────┬──────────────────────────────────────┬─────────────────────────────────────────┐
  │                        Approche                        │                    Outils                    │               Avantage               │                  Coût                   │
  ├────────────────────────────────────────────────────────┼──────────────────────────────────────────────┼──────────────────────────────────────┼─────────────────────────────────────────┤
  │ terra::rast() (ou stars::read_stars()) sur GRIB2       │ dépend du backend GDAL compilé avec libgrib2 │ direct dans R                        │ demande GDAL ≥ 3 avec support grib      │
  ├────────────────────────────────────────────────────────┼──────────────────────────────────────────────┼──────────────────────────────────────┼─────────────────────────────────────────┤
  │ Conversion préalable GRIB2 → NetCDF avec cdo ou wgrib2 │ shell externe                                │ NetCDF lu nativement par ncdf4/terra │ un script de conversion                 │
  ├────────────────────────────────────────────────────────┼──────────────────────────────────────────────┼──────────────────────────────────────┼─────────────────────────────────────────┤
  │ Lecture via rNOMADS ou gribr                           │ packages R dédiés                            │ tout en R                            │ packages plus fragiles, moins maintenus │
  └────────────────────────────────────────────────────────┴──────────────────────────────────────────────┴──────────────────────────────────────┴─────────────────────────────────────────┘

  Volume : 57 GB en 0.5° est démesuré pour un projet de classe centré sur des moyennes mensuelles globales. Je te recommande fortement de partir du 2.5° (3.5 GB) qui suffit largement à une corrélation globale CO2 ↔ température / humidité. Le 0.5° n'a d'intérêt que si tu veux faire des cartes régionales fines.

  6. Variables disponibles dans les fichiers pgb

  Les produits pgb (« pressure grid binary ») contiennent typiquement, sur plusieurs niveaux de pression, la température, le géopotentiel, l'humidité relative, les composantes du vent (U/V), la vitesse verticale, la pression de surface,
   et les précipitations totales. Pour confirmer la liste exacte présente dans tes fichiers, il faudra exécuter wgrib2 -V sur un fichier (ex. pgbl04.gdas.197901.grb2) — je peux te générer le script si tu veux.

  - Choix de résolution : je conseille 2.5° comme base de travail.

  Bénéfice analytique : avec all-sky et clear-sky en SW comme en LW, tu peux calculer les Cloud Radiative Effects (CRE) :
  - CRE_SW = (DSWRF - USWRF) - (CSDSF - CSUSF)
  - CRE_LW = (DLWRF - ULWRF) - (CSDLF - CSULF)
  - CRE_net = CRE_SW + CRE_LW

  → permet de séparer le forçage radiatif direct du CO2 de la rétroaction des nuages, ce qui est exactement le cœur scientifique de ton sujet.
